## Критический баг: SPACEMOON

```

is_active: TRUE
total_sold_bnb: 0  ← ничего не продано
```

**Что произошло:**
- Токен SPACEMOON вырос до **4.955x** от цены входа
- Трейл-хай обновился (бот зафиксировал пик цены)
- Но TP стадии (tp_index = 0) не сработали
- После restart контейнера **позиция потеряна из памяти**
- BSC scanner загружает токены только при запуске, не восстанавливает из DB
- Все TP-проверки и stop-loss происходят только в in-memory Map
- При restart → Map пустая → SPACEMOON никогда больше не проверялась
- Прошло 2 дня — цена, скорее всего, рухнула

**Текущий статус SPACEMOON:** заброшена, `last_activity_at` = дата покупки = ни разу не обновлялась после входа. Это баг №1 в BSC scanner.

## Анализ причин убытков

### Причина #1: НЕТ восстановления позиций после restart (КРИТИЧНО)
**Убыток:** -0.003 BNB (SPACEMOON) + потенциальные будущие потери
**Суть:** BSC/Base scanner хранит позиции в `Map<string, Position>`. После `docker restart` Map = пустой. DB не опрашивается при старте.
**В отличие от Solana autobuy:** Raydium scheduler загружает активные позиции из БД при старте через `SELECT * FROM autobuy_jobs WHERE active=true`.
**Фикс:** добавить startup-reload в `bsc-scanner/src/monitor.ts`:
```typescript
async function reloadPositionsFromDB(): Promise<void> {
  const { rows } = await query(`SELECT * FROM bsc_positions WHERE is_active=true`, []);
  for (const row of rows) {
    activePositions.set(row.contract_address, { ...row });
  }
  console.info(`[bsc-monitor] reloaded ${rows.length} positions from DB`);
}
```

### Причина #2: Стратегия "buy the dip" неправильная для BSC мемов
**Суть:** BSC scanner ищет токены с mcap > $20M у которых pc24h ≤ -10% ("покупаем на откате").
- 布布: китайские иероглифы = типичная BSC мем-монета. Mcap мизерный, нет объёма
- Korico: микрокап, нет ликвидности
- ELITE: купили ДВАЖДЫ один и тот же токен! Одинаковый contract address 0x567ad9c7...

**Фильтры слишком слабые:** токены проходили скрининг при mcap < $20M (текущий лимит). SPACEMOON сейчас стоит $2.1M — значит когда покупали он тоже был микрокапом.

**Лог показывает:** сейчас BSC scanner отклоняет все токены из-за `mcap < $20M`. Это проблема — стратегия "buy the dip" работает для mid-cap (> $20M), не для мемов.

### Причина #3: Дублирующиеся покупки одного токена
**ELITE куплен дважды:**
- ELITE #1: contract 0x567ad9c7..., bought at 15.06 21:39 (закрыт STOP_LOSS)
- ELITE #2: contract 0x567ad9c7..., bought at 16.06 03:12 (time limit, -80%)

BSC scanner НЕ проверял что уже есть открытая позиция на этот контракт. После STOP_LOSS на ELITE в 21:39 — в 03:12 тот же токен куплен снова. Это ошибка в фильтре дубликатов.

### Причина #4: Время лимит без прибыли
Все 4 TIME_LIMIT сделки вышли ниже входа:
- 布布×2: -19% / -21% — токены просто не росли
- ELITE #2: -80% — токен продолжал падать всё время лимита

Время лимит защитило от бóльших потерь, но базовая проблема — **входили в токены без импульса** (покупка "на откате" → дальнейший откат).

## BSC Stратегия: "Buy the Dip" — почему не работает

```
Текущие фильтры BSC scanner:
- pc24h ≤ -10% (токен упал за 24ч)
- mcap > $20M (пока ни один не проходил, много микрокапов)
- liq > $100k (фильтр ликвидности)
- DEX: PancakeSwap v2

Проблема:
1. Токены mcap < $20M = нет ликвидности для выхода
2. "На откате" на BSC = часто продолжение тренда вниз (нет дна)
3. SPACEMOON: купили на откате → выросло до 5x → не продали
4. Стратегия показала 0 из 5 побед за 2 дня
```

**Альтернативный подход для BSC:**
- Скопировать успешный подход Raydium: искать токены с РОСТОМ (pc1h ≥ 5%), не падением
- BSC_MIN_LIQUIDITY_USD=50000 (реальная ликвидность)
- Только microcap мемы с momentum (как FOUR, BRETT, BONK на BSC)
- TP1 сразу при +30% (не ждать 2.0x как сейчас)
