## 🧠 LLM АРХИТЕКТУРА (scorer.ts — финальная версия v4)

### Принцип: дешёвый анализ → дорогое решение

```
matchNewsToMarket() + scorePosition() → callLLMFree()
  FREE tier, любой сигнал, много вызовов

processNewsSignal() при EV≥0.12 → callLLMPremium() (FINAL GATE)
  PREMIUM, 1× на каждую реальную сделку
  Если Claude недоступен → fallback на callLLMFree (non-blocking)
```

### callLLMFree() — Groq → DeepSeek → OpenAI

```typescript
// Groq rate limiting: promise chain serializer
// _groqChain = module-level, .then() atomic в JS single-thread
// 5.5s между вызовами = ~10.9 calls/min × ~470 tokens = ~5,100 TPM (лимит 6,000)

async function callLLMFree(content, maxTokens):
  1. acquireGroqToken() → wait for slot (5.5s gap)
  2. POST api.groq.com — llama-3.1-8b-instant
     При 429: wait 5s → retry once → fallback
  3. DeepSeek deepseek-chat           ← BACKUP (нужен баланс ⚠️)
  4. OpenAI gpt-4o-mini               ← LAST RESORT
  5. throw "No LLM available"
```

### callLLMPremium() — Claude → fallback

```typescript
async function callLLMPremium(content, maxTokens):
  1. claude-haiku-4-5-20251001        ← ⚠️ 400 (кредиты/тир)
  2. claude-3-5-haiku-20241022        ← ⚠️ 400 (та же проблема)
  3. → callLLMFree() fallback         ← используется сейчас
```

### Slim prompts (ключ к работе в Groq TPM лимите)

| Параметр | Было | Стало | Токены |
|---|---|---|---|
| Рынков в промпте | 60 | **10** | 800 → 175 токенов |
| Market ID в JSON | `"0x9b6fef..."` (66 chars) | **числовой index 0-9** | 66 → 1 char |
| Заголовок рынка | 80 chars | **60 chars** | |
| Новость | 400 chars | **200 chars** | |
| Completion tokens | 200 | **120** | |
| **Итого matchNews** | ~1,100 | **~470 tokens** | |
| **Итого scorePos** | ~490 | **~250 tokens** | |
| **TPM при 17 headlines** | ~18,700 | **~4,760** | ✅ под лимитом |

### Полный путь сигнала

```
Источник → processNewsSignal(text, source)
    │
    ├── getMarketsFromDb()           → 94 рынка, top 10 берётся по volume
    │
    ├── matchNewsToMarket(text)      ← callLLMFree (Groq @ 5.5s gap)
    │   Промпт: новость + 10 рынков + числовые индексы
    │   Ответ: {match, idx:0-9, outcome, relevance}
    │   Пропуск если relevance < 50
    │
    ├── scorePosition(market, outcome) ← callLLMFree (Groq @ 5.5s gap)
    │   Промпт: рынок + сигнал + текущая цена
    │   Ответ: {ai_prob_yes, ev, confidence, reasoning}
    │   Пропуск если EV < 0.12 или confidence=LOW
    │
    ├── FINAL GATE: callLLMPremium() ← 1× на сделку
    │   {approve:true/false, reason}
    │   Non-blocking (fallback на Groq если Claude недоступен)
    │
    ├── INSERT polymarket_signals
    │
    └── tryOpenPosition() → INSERT polymarket_positions (is_dry_run=true)
```

### Strategy 2 — GDELT Trend Clusters (**ЛУЧШАЯ**)
```
Source:    trend_clusters.main_title (GDELT новости, последние 60 мин)
Signal:    main_title → processGdeltSignal → matchNewsToMarket
Best for:  Trump, G7, Elon, геополитика, спорт → высокий матч
Warning:   Использовать main_title, НЕ summary (summary содержит HTML)
Hit rate:  ~20-40% матчей
```

### Strategy 3 — RSS Headlines
```
Source:    CoinDesk, CoinTelegraph, Decrypt, BBC World (Reuters недоступен с VPS)
Cycle:     fetchRssHeadlines() → 17 headlines каждые 10 мин
Process:   for..of (sequential), return после первого сигнала
Hit rate:  1-2 сигнала за 10 headlines обработки
Proof:     Первый сигнал от rss:coindesk — France FIFA World Cup
```

### Strategy 4 — Volume Spike Detection
```
Source:    Gamma API live цены vs DB cached цены
Signal:    volume_change ≥ 50% + price_change < 3% → информационная асимметрия
Frequency: Каждые 30 мин
Hit rate:  Редкий (<2 раза/день), но сильный сигнал
```

### Strategy 5 — GDELT v2 Direct Search [NEW v5]
```
Source:    api.gdeltproject.org/api/v2/doc/doc — прямой keyword search по заголовкам
Signal:    keyword из market title → article headlines → processNewsSignal
Coverage:  любые актуальные новости по теме рынка (не только кластеры)
Best for:  Рынки с конкретными именами: "Trump", "FIFA", "Fed rate", "Ukraine"
Warning:   Только top-5 рынков (по volume) × top-3 статьи = ограниченный охват
```

### Bug #1: Claude 400 на всех моделях (20.06.2026)

```
Симптом: 0 сигналов за 2 дня
Причина: GROQ_API_KEY и DEEPSEEK_API_KEY не были добавлены в VPS .env
Fix:     Добавлены оба ключа через SSH (21.06.2026)
         docker compose up -d --no-deps polymarket-bot (NOT docker restart!)
```

### Bug #3: Burst concurrent Groq calls → 429 (21.06.2026)
```
Симптом: Groq 429 сразу при запуске (17 корутин из RSS одновременно)
Причина: Все processNewsSignal старты вызывают callLLMFree без задержки
Fix:     acquireGroqToken() — promise chain serializer:
         _groqChain: each caller appends token = _groqChain.then(delay)
         JS single-thread гарантирует атомарность .then() вызова
```

### Bug #4: Groq token rate limit (TPM) → постоянные 429 (21.06.2026)
```
Симптом: Groq 429 при каждом вызове даже с 2.3s задержкой
Причина: Groq TPM limit = 6,000 tokens/min
         60 markets JSON × 160 chars = 9,600 chars ≈ 2,400 tokens (рынки)
         20 markets: 3,200 chars ≈ 800 tokens
         + новость (400 chars) + completion (200 tokens) = ~1,100 tokens/вызов
         7 вызовов × 1,100 = 7,700 tokens > 6,000/min → 429!

Fix применён:
  1. markets.slice(0, 10) — только топ-10 по volume
  2. Числовой index вместо полного market hash (66 chars → 1 char)
  3. news[:200] (было [:400]), title[:60] (было [:80])
  4. completion: 120 (было 200)
  5. gap: 5,500ms (было 2,300ms)
  Результат: ~470 tokens/call × 10.9 calls/min = ~5,100 TPM ✅ (лимит 6,000)

Диагностика токенов:
  Groq API (node test): 200 OK, remaining=14,398 requests/day ✅
  Проблема была не в request limit а в TPM (tokens per minute)
```

### Bug #5: scorePosition JSON parse error (21.06.2026) — FIXED
```
Симптом: "Expected double-quoted property name in JSON at position 80"
Причина: LLM вернул малформированный JSON — {'YES'} одинарные кавычки, trailing comma
Fix:     response_format: { type: 'json_object' } добавлен в ВСЕ axios.post вызовы
         (Groq, DeepSeek, OpenAI — все поддерживают OpenAI-совместимый параметр)
         API гарантирует валидный JSON — parse errors полностью устранены

```

## 📐 ПАРАМЕТРЫ TP/SL И МАТЕМАТИКА EV

| Параметр | Значение | Обоснование |
|---|---|---|
| Take Profit | **+35%** от entry | $0.20 → $0.27 (на $10 = +$3.50) |
| Impulse TP | **+22% за ≤20 мин** | Быстрое движение = фиксируем |
| Stop Loss | **-40%** от entry | $0.20 → $0.12 (потеря -$4) |
| Time Limit | **2 часа** | Prediction markets — медленные движения |
| Размер позиции | **$10 USDC** | Безопасный минимум для теста |
| Max позиций | **3** | Диверсификация, не перегруженность |
| Min EV | **12%** | Покрывает слипадж + ошибки модели |

**EV при 65% Win Rate (цель):**
```
Avg win:  +35% × $10 = +$3.50
Avg loss: -40% × $10 = -$4.00
EV/trade: 0.65 × 3.50 - 0.35 × 4.00 = $2.275 - $1.40 = +$0.875
EV%:      +8.75% per trade
30 trades: +$26.25 на $300 капитала (+8.75% total)
```
