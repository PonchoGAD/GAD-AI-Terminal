## 1. Raydium Autobuy — почему нет сделок

### Ключевой факт из логов

```
❌ No entries — liq=58 age=17 mom=0 ratio=0 cooldown=0 ...
```

**`mom=0`** — ни один токен не доходит до фильтра по momentum. Все 82 пары отсеиваются на Gate 1 (liq=58) или Gate 2 (age=17) ещё до проверки pc1h/pc5m.

### Разбор Gate 1 (✗liq) по конкретным токенам

| Токен | Liq | Vol1h | Pc1h | Причина блока |
|---|---|---|---|---|
| ███ | $15,347 | $7,698 | +107% | ✗liq — `liq < 25000` (hardcoded в старом dist) |
| CATWIF | $7,250 | $4,112 | +36% | ✗liq — liq < $12k |
| drooling | $64,907 | — | +210066% | ✗age — age=334h (> 12h max) |
| POKÉFIGHT | $35,245 | — | +38.8% | ✗age — age=64.2h (> 12h max) |
| WOJAK | $111,488 | $23,159 | -0.3% | ✗liq — **предположительно MAX=80k ещё в dist** |
| SOL/RENDER/EOS/SEI | $100M-$2.3B | — | — | ✗liq — liq > MAX_LIQ |

### Критическая проблема: hardcoded значения в compiled dist

Текущий исходник (`auto-signal.ts:435,439`):
```typescript
const RAYDIUM_MIN_LIQUIDITY_USD = 12000; // hardcoded 12k
const RAYDIUM_MAX_LIQUIDITY_USD = 120000; // hardcoded 120k
```

Но VPS запускает **старый compiled dist**, в котором эти значения были либо другими, либо env-variable-зависимыми с устаревшими дефолтами. Признаки:

- **"███"** ($15,347 liq, +107% pc1h) блокируется `✗liq` — это означает что MIN в dist = 25000, не 12000. Иначе $15k > $12k = прошёл бы.
- **WOJAK** ($111,488 liq) блокируется `✗liq` — если MAX = 120k, то $111k < $120k = должен пройти. Значит либо MAX всё ещё 80k в dist, либо включён фильтр RAYDIUM_MIN_VOLUME_H1_USD.

Patch (autobuy.patch.js) исправил `|| '80000'` → `|| '120000'` для MAX. Но MIN (25k hardcoded) не был патчен.

### Реальная причина mom=0: комбинация строгих фильтров + FEAR рынок

Из VPS `.env` (подтверждено):
```
RAYDIUM_MIN_PC1H=5      → в FEAR режиме dist использует Math.max(5, 10) = 10%
RAYDIUM_MAX_PC1H=25     → очень узкое окно!
RAYDIUM_MIN_PC5M=5      
RAYDIUM_MIN_VOL_LIQ_RATIO=0.20   ← строго (дефолт 8%)
RAYDIUM_MIN_VOL5M_LIQ=0.08       ← активен
```

**Допустимое окно в FEAR: pc1h ∈ [10%, 25%]** — крайне узко.

Из логов: ни один токен не попадает в это окно:
- "███" pc1h=107% → PASS лик, но ≥Gate2 age OK → FAIL gate3 `✗mom` (107 > 25)  
- CATWIF pc1h=36% → FAIL `✗liq` (liq=$7,250 < $12k)
- POKÉFIGHT pc1h=38% → FAIL `✗age` (64h > 6h max)
- WOJAK pc1h=-0.3% → FAIL `✗liq` (FEAR floor: $111k > $25k OK, но pc1h=-0.3% < 10%)

Ждём: FEAR рынок F&G=23. В такие периоды в Raydium появляются единичные выстрелы с pc1h 10-25%. Это нормальная пауза.

**Однако MAX_PC1H=25 слишком строгий в FEAR:** в страх-рынке токен с 30-40% за час — это НЕ "уже на вершине", это ещё ранняя стадия. Рекомендую поднять до 40-45%.

### Необходимые исправления

**Патч для MIN_LIQ в dist:**

```javascript
// Добавить в autobuy.patch.js:

  );

  console.log('[patch] auto-signal.js: MIN_LIQ hardcoded 25k → env-driven 12k');
}
```

## 4. Base Scanner — скам-токены cbXRP/cbADA

### Почему они проходили фильтры

**security-shield.ts — 3 слоя:**

```typescript
// Layer 1: Basescan verification
if (verResp.data?.status !== '1') return { isSafe: false, reason: 'CONTRACT_NOT_VERIFIED' };
// ← ЕСЛИ BASESCAN_API_KEY не установлен — слой 1 пропускается!

// Layer 2: GoPlus Labs
const report = goplusResp.data?.result?.[address];
if (!report) return { isSafe: true }; // ← FAIL-OPEN
if (report.is_honeypot === '1') return { isSafe: false };
if (report.slippage_modifiable === '1') return { isSafe: false };
// ← cbXRP/cbADA: GoPlus видит их как "безопасные" ERC-20
// Honeypot: '0', tax: 0%, mintable: '0' — технически валидные токены
```

**Реальная причина bypass:**

cbXRP и cbADA — это кросс-чейн импersonators:
- Технически корректные ERC-20 на Base (не honeypot, 0% tax)
- GoPlus возвращает `is_honeypot: 0`, `sell_tax: 0` — всё "безопасно"
- Basescan слой мог быть пропущен (нет API key или timeout)
- **Ловушка**: они позволяют продать маленькие суммы но при попытке продать с прибылью могут заблокировать (GoPlus не симулирует крупные продажи)

**Функция `isChainImpersonator()` уже была в scanner.ts** (строка 17-22 в исходнике), но в **скомпилированном dist** её вызов из `passesFilter()` отсутствовал до сегодняшнего патча.

### Исправления применены (23.06.2026)

✅ **Patch 3 (base-scanner.patch.js):** `isChainImpersonator()` теперь вызывается из `passesFilter()`:

```javascript
// Line 190 в dist scanner.js (после патча):
if (isChainImpersonator((t.symbol || ""))) return "chain_impersonator: " + t.symbol;
```

Подтверждение в логах:
```
[base-scan] ✗ cbADA chain_impersonator: cbADA
```

✅ **MAX_PC1H снижен** в исходнике: `100% → 30%` (строка 33 scanner.ts) — предотвращает покупку токенов которые уже выросли на 55% (кейс B20: вход +55%, итог -47%).

### Адреса скам-токенов (из DB: `autobuy_jobs WHERE chain='base'`)

База не вернула данных — либо таблица `autobuy_jobs` не имеет колонки `chain`, либо токены в `base_positions`. Нужно уточнить:

```sql
-- На VPS:
SELECT symbol, contract_address, bought_at, pnl_usd FROM base_positions 
WHERE symbol ILIKE 'cb%' OR symbol ILIKE '%XRP%' OR symbol ILIKE '%ADA%'
ORDER BY bought_at DESC LIMIT 10;
```

### Оставшиеся уязвимости

| Слабое место | Описание | Риск |
|---|---|---|
| `isChainImpersonator` symbol list | Список из 33 символов — можно обойти `cbXRP2`, `CBXRP`, `xcbXRP` | MEDIUM |
| GoPlus fail-open | `if (!report) return { isSafe: true }` — новые токены без GoPlus данных проходят | HIGH |
| Basescan skip без API key | Весь Layer 1 пропускается если `BASESCAN_API_KEY` не задан | HIGH |
| `volume_5m` не используется | В `mapDexPair()` поле `volume_5m` не маппируется из DexScreener | LOW |

**Рекомендация — добавить в security-shield.ts:**

```typescript
// Усиленный fail-closed для новых токенов (возраст < 1h):
if (!report && isNewToken) {
  return { isSafe: false, reason: 'NEW_TOKEN_NO_GOPLUS_DATA' };
}
```
