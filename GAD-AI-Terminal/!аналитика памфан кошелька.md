## Анализ причин потерь

### Причина #1: Баг VersionedTransaction (убыток: ~-0.50 SOL)
**Период:** 11-13.06.2026 (первые 5 HOT тоже пострадали)
**Затронуто:** 21+ сделок → 0 SOL возвращено
**Проблема:** При продаже бот пробовал `Transaction.from(versioned_bytes)` как fallback → exception → позиция застревала.
**Критический случай DRILL:** Токен вырос до 58x, sell TX упал 3 раза, потеряли всю позицию (0.03 SOL).
**Фикс применён:** 13.06.2026 ~18:16 (см. Decisions Log)
**Вывод:** Без этого бага win rate фазы 1-2 мог быть 30-40%+.

### Причина #2: Слишком высокий mcap при входе в HOT стратегии (убыток: ~-0.18 SOL)
**Период:** 13.06.2026
**Проблема:** HOT поллер покупал токены с mcap 100-192 SOL (15,000-29,000 $).
При таком mcap движение уже произошло — покупка на хвосте.
**MCap > 100 SOL = памп уже был.** Нужен был вход до 50 SOL.
**Фикс:** Снижение BONDING_HOT_MAX_MCAP_USD до $8,000 (≈ 53 SOL при $150/SOL).

### Причина #3: DexScreener лаг 30-60 секунд (убыток: ~-0.12 SOL)
**Период:** 14-15.06.2026 MOVER
**Проблема:** DexScreener обновляется каждые 30-60с. К моменту когда мы видим pc5m=20% и покупаем → прошла 1 минута → мы уже на вершине спайка.
**MOVER Jun 14 mcap 35-82 SOL:** большинство вышли за 50-96% (не 0) — то есть фактически продавались ниже входа.
**Вывод:** DexScreener-based стратегия структурно проигрышна для быстрых bonding curve токенов.
**Решение:** SOL Velocity Tracker на PumpPortal WebSocket (нет лага).

### Причина #4: GRAD стратегия — неправильный тезис (убыток: -0.112 SOL)
**Период:** 15.06.2026
**Проблема:** Покупка при mcap 350-400 SOL = токен почти вышел с bonding curve.
- Ликвидность минимальна → наш sell дампит цену
- Токен вот-вот уйдёт на Raydium → PumpPortal больше не работает
- 0/9 сделок прибыльных
**Отключено:** `GRAD_HUNTER_ENABLED=false` ✅

### Причина #5: WebSocket sell connection обрывался (убыток: ~-0.05 SOL)
**Период:** 15.06 после 15:30
**Признак:** 6 MOVER сделок подряд вернули ровно 0 при mcap 110-157 SOL. До этого (утром того же дня) такой же mcap диапазон давал частичные возвраты.
**Вероятная причина:** Контейнер autobuy перезапустился или WebSocket соединение потерялось → sell TX не инициировались → time limit истёк → попытка sell в пустой кривой.
**Нужна проверка:** reconnect logic в bonding WebSocket.

## SOL Velocity Tracker — новая стратегия (17.06.2026)

### Как работает
- PumpPortal WebSocket: получает каждый трейд в реальном времени
- Зона входа: 25-80 SOL в кривой (не mcap, а сколько SOL уже внесено)
- Velocity: сумма всех `solAmount` за последние 60s ≥ 3 SOL
- Anti-whale: пропуск если одна покупка > 5 SOL
- Unique buyers: ≥ 8 за последние 60s
- Time limit: 90s (очень жёсткий)
- TP: 1.5x → 100% (one-shot)
- Stop: -12%

### Почему лучше MOVER
| Параметр | MOVER | SOL Velocity |
|---|---|---|
| Задержка данных | 30-60с | 0мс (реальное время) |
| Метрика | % изменение цены | Поток SOL/60с |
| Манипуляция | Легко накачать % | Сложно — нужны реальные деньги |
| Anti-whale | Нет | Да (>5 SOL = пропуск) |
| Входная зона | mcap в $ | SOL в кривой (25-80) |

### Данных по velocity пока нет
Стратегия добавлена 17.06.2026. Нужно собрать 20-30 трейдов для анализа.

## Оптимальный сценарий для pump.fun

**Гипотеза основана на анализе 3 победителей:**

```
Единственная стратегия, которая работает: SOL Velocity
- Источник: PumpPortal WebSocket (0 мс лаг)
- Зона: 25-80 SOL в кривой
- Сигнал: ≥3 SOL за 60с от ≥8 уникальных покупателей
- Anti-whale: нет отдельных покупок >5 SOL

TP конфигурация (основана на реальных выходах побед):
- TP1: 1.2x → 70% (поймать первый спайк, все 3 победы были 1.07-1.88x)
- TP2: 1.6x → 20% (задержаться если продолжает)
- TP3: 2.5x → 10% (moon bag)
- Trail stop: 8% (был 15% — слишком широкий для bonding)
- Time limit: 90s (без изменений — правильный)
- Stop-loss: -10% (был -12%)

Размер позиции: 0.012-0.015 SOL (как сейчас)
Дневной лимит: 0.15-0.20 SOL (10-15 сделок)
```

**Ожидаемый результат при оптимальном сценарии:**
- Win rate: 15-25% (vs текущих 4%) — за счёт убранного DexScreener лага
