## F&G Guard — ДОПОЛНИТЕЛЬНАЯ ЗАЩИТА

`checkFGHistorySafe()` — W3 sniper **полностью заблокирован** при недостаточном рынке:

```
alternative.me /fng/?limit=5 → последние 5 дней F&G
Если хотя бы 1 день < 45 → AUTO-ENABLE BLOCKED

Текущий F&G (01.07.2026): 11,15,12,18,15 → BLOCKED (FEAR рынок)
```

**Логика:** W2/W3 несколько раз слили SOL до 0. Трейдинг на pump.fun разрешён только при устойчивом BULL рынке (5 дней подряд F&G > 45). Один BULL день = dead cat bounce, не тренд.

**В SHADOW режиме:** guard не блокирует накопление данных — бот продолжает делать shadow trades даже при F&G=11. Только в LIVE режиме guard действительно останавливает активность.

**Разблокировка:** F&G > 45 × 5 дней подряд → guard снимается автоматически (без перезапуска).

### Почему v1 показал 0% WR (корневая причина)

`subscribeTokenTrade` на PumpPortal требует платный API ключ. Без него подписка принималась, но данные НЕ приходили. `current_price` оставался равным `entry_price` всё время → mult=1.000 всегда → стагнация через 3 минуты.

**v2 исправление:** `conn.onAccountChange(bondingCurvePDA, ...)` — стандартный Solana RPC, работает с бесплатным Helius. Обновляет `vSol/vTokens` при каждом трейде на кривой.

**Новая проблема:** accountSubscribe срабатывает ТОЛЬКО если кто-то торгует токеном. Мёртвые токены (без покупателей после dev buy) не триггерят callback → price stuck at entry → stagnation exit через 3 минуты. Это ПРАВИЛЬНОЕ поведение — лучше выходить за 3 мин чем держать 15 мин мёртвый токен.

### Логика входа (v3)

```
PumpPortal WebSocket txType='create'
    ↓
Фильтры:
  1. dev_buy_sol ≥ 0.20 SOL (девелопер показал commitment)
  2. vSol ≤ 30.30 SOL (anti-bundle: если выше — bundlers уже зашли в той же транзакции)
  3. Без rug-keywords в названии
  4. Max 2 позиции одновременно (↓ с 3)
  5. Max 12 покупок в день (↓ с 15)
  6. Dev reputation check (analyzeDevReputation, 2s timeout, fail-open):
     - isSerialScammer → SKIP
     - score < 40 → SKIP
     - score ≥ 40 → PROCEED
    ↓
Bonding curve math:
  - vSol / vTokens = entry_price
  - token_amount = vTokens × BUY_SOL / (vSol + BUY_SOL)
    ↓
Открыть shadow позицию + accountSubscribe на bonding curve PDA
→ записать в shadow_trades
```

### Логика выхода (v3, каждые 10 секунд)

```
1. mult ≤ 0.93 (-7%) → STOP_LOSS немедленный выход (↑ с 8% до 7%)
2. 45s И mult < 1.01 → STAGNATION_45s (нет покупателей вообще)
3. 90s И mult < 1.03 → STAGNATION_90s (не удержал +3% → импульс мёртв)
4. 180s И mult < 1.05 → STAGNATION_180s (финальная проверка мёртвого токена)
5. mult ≥ 2.20x → продать 80%, держим 20% moon-bag (TP3, ↓ с 2.5x)
6. mult ≥ 1.60x → продать 50% (TP2, ↓ с 1.8x)
7. mult ≥ 1.25x → включить trailing stop 8% (TP1, ↓ с 1.35x, trail ↓ с 10%)
   trailing: если current < peak × 0.92 → ВЫХОД
8. 15 минут истекли:
   - mult ≥ 1.15x → TIME_LIMIT_WIN (+X%)
   - mult 0.90-1.15x → TIME_LIMIT_FLAT (~0%)
   - mult < 0.90x → TIME_LIMIT_LOSS (-X%)
```

## Bonding Curve Math (как считается цена)

```
pump.fun константы:
  VIRTUAL_SOL_RESERVES   = 30           (SOL в виртуальных резервах при старте)
  VIRTUAL_TOKEN_RESERVES = 1,073,000,191 (токенов в виртуальных резервах)

Формула цены:
  price = vSolInBondingCurve / vTokensInBondingCurve

Формула покупки (сколько токенов за 0.015 SOL):
  K = vSol × vTokens
  new_vTokens = K / (vSol + 0.015)
  tokens_received = vTokens - new_vTokens

Обновление цены (v2 — Helius accountSubscribe):
  bonding curve account layout:
    bytes 0-7:   discriminator
    bytes 8-15:  virtualTokenReserves (u64, base units)
    bytes 16-23: virtualSolReserves   (u64, lamports)
  price = (vSolLamports / 1e9) / vTokens
```

## Как отслеживать результаты

### Telegram команды
```
/w3stats       — последние 12 часов
/w3stats 24    — последние 24 часа
/w3stats 48    — последние 48 часов
```

### SQL напрямую
```sql
-- Все shadow trades за 24ч
SELECT symbol, status, outcome_pct, ROUND(EXTRACT(EPOCH FROM (outcome_at - created_at))/60) as min, created_at
FROM shadow_trades
WHERE strategy='w3-sniper'
  AND created_at > NOW() - INTERVAL '24 hours'
ORDER BY created_at DESC;

-- Статистика
SELECT
  COUNT(*) total,
  COUNT(*) FILTER (WHERE status!='open') closed,
  COUNT(*) FILTER (WHERE outcome_pct >= 10) wins,
  ROUND(AVG(outcome_pct) FILTER (WHERE status!='open'), 2) avg_pct,
  ROUND(AVG(EXTRACT(EPOCH FROM (outcome_at - created_at))/60) FILTER (WHERE status!='open'), 1) avg_hold_min
FROM shadow_trades WHERE strategy='w3-sniper';

-- По типу выхода
SELECT
  CASE
    WHEN status='tp1_hit' THEN 'WIN'
    WHEN status='stopped' AND outcome_pct < -5 THEN 'STOP_LOSS'
    WHEN status='stopped' AND outcome_pct BETWEEN -1 AND 1 THEN 'FLAT_EXIT'
    ELSE 'OTHER'
  END as exit_type,
  COUNT(*), ROUND(AVG(outcome_pct), 2) avg_pct
FROM shadow_trades
WHERE strategy='w3-sniper' AND status!='open'
GROUP BY 1 ORDER BY 2 DESC;
```

## Когда переключать в LIVE режим

**Критерии для LIVE:**
- WR ≥ 20% на закрытых позициях
- EV > 0 (среднее ожидаемое значение положительное)
- Минимум 30 закрытых позиций
- Баланс W3 ≥ 0.05 SOL
- F&G > 45 × 5 дней подряд (guard автоматически разблокируется)

**Как включить LIVE:**
```bash
# На VPS:
nano /opt/gad-ai-terminal/GAD-AI-Terminal/.env
# Изменить: W3_SNIPER_SHADOW=false
docker compose up -d --no-deps autobuy
```

> ⚠️ **НЕЛЬЗЯ** переключать в LIVE если:
> - F&G хотя бы 1 из 5 дней < 45 (F&G guard заблокирует автоматически)
> - EV < 0 на последних 30+ трейдах
> - WR < 20%
> - W3 баланс < 0.05 SOL

1. **НИКОГДА** не включать LIVE без WR ≥ 20% на 30+ закрытых трейдах

5. **Min dev buy = 0.15 SOL** — не снижать, нужен реальный commitment от разработчика
6. **15 минут — жёсткий лимит** — мемкоины не держаться дольше
7. **accountSubscribe НЕ стреляет** на мёртвых токенах — это нормально (stagnation exit за 3 мин)
