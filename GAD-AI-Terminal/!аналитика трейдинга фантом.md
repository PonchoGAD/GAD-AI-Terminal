### ⚠️ ЧТО НЕ БЫЛО РЕАЛИЗОВАНО (и почему)

**НЕ реализовано: Token-2022/pumpswap через Jupiter**

Рекомендация предлагала добавить `onlyDirectRoutes: 'false'` и `asLegacyTransaction: 'false'` в Jupiter API запрос якобы для поддержки Token-2022 (pumpswap). Это **технически неверно** по следующим причинам:

1. **Jupiter симуляция** падает с `custom error 0x1` на Token-2022 — это не проблема флагов routing, а несовместимость ATA (Associated Token Account) программ. `asLegacyTransaction: false` уже стоит по умолчанию и ничего не меняет.
2. Мы **уже пробовали** pumpswap как Source 6 — результат: **66 phantom транзакций** (записи с `bought_at=NULL, total_sold_sol=0`) = деньги на входе, ничего на выходе.
3. Pumpswap токены используют Token-2022 программу. Jupiter **не может** их продать после покупки даже если купит. Продажа = ещё одна партия phantoms.
4. Решение было: **полностью удалить** pumpswap источник. Это правильное решение, откатывать нельзя.

**Примечание:** RAYDIUM_MIN_AGE_SEC=1800 добавлен в .env но в коде этот параметр не читается — минимальный возраст управляется хардкодированной логикой (`liq < $45k AND age < 60min → reject`). Параметр безвреден но не активен.

**Примечание:** GeckoTerminal `/networks/solana/new_pools` возвращает преимущественно pumpswap пулы — `geckoPoolToPair()` их фильтрует (GECKO_DEX_MAP не включает pumpswap). Source 6 готов но неэффективен пока на Raydium нет активных новых листингов.

### Торговый поток (полный pipeline)

```
startAutobuyScheduler()
    │
    ├── [каждые 15с] checkMarketBuyGate()
    │   └── F&G + BTC dominance + mcap change → health 0-100
    │       health < 20 → STOP all buys
    │
    ├── [каждые 120с] processRaydiumOpportunities(walletAddress)
    │   ├── getMarketRegime() → EXTREME_FEAR/FEAR/NEUTRAL/BULL/EUPHORIA
    │   │   EXTREME_FEAR (F&G < 13) → СТОП
    │   ├── fetchRaydiumPairs() → ~90 кандидатов из 5+ источников
    │   ├── Gate 1: liq $30k-$80k + FEAR floor $35k
    │   ├── Gate 2: age 1h-6h + no microcap < 60min
    │   ├── Gate 3: momentum pc5m/pc1h/b-s ratio/buys5m
    │   ├── Gate 3b: B/S ratio ≤ 3.0x
    │   ├── Gate 3c: buys5m ≥ 2, 5m buyers > sellers
    │   ├── Gate 3d: vol5m/liq ≥ 10%
    │   ├── Gate 4: vol1h/liq ≥ 20%, vol acceleration
    │   ├── recentlyBought() / previouslyLost() cooldowns
    │   ├── analyzeTrend() / detectHype() / assessLiquidity() / detectBotActivity()
    │   ├── checkHolderMomentum() → Birdeye ≥ 70 holders
    │   ├── checkTopHolder() → top holder < 50% supply
    │   └── INSERT autobuy_jobs (label: auto:raydium_scan:liqXXk:freshYh:t1:fear)
    │
    ├── [каждые 15с] runBuyCycle()
    │   └── fetchAndLockDueJobs() → executeAutoBuy() via Jupiter
    │       → verifyOnChain balance → createSellStages()
    │
    └── [каждые 1с] checkAndExecuteSells() (fast loop)
        ├── getPriceSolViaDS() — Jupiter Lite → DexScreener fallback
        ├── HARD CAP: T1=30min, T2=60min, T3=4h (независимо от активности)
        ├── EARLY TRAIL: peak × (1 - earlyTrailPct) > entry×1.02 → продаём
        ├── TRAILING STOP: после TP1, peak × (1 - trailPct)
        ├── STOP LOSS: entry × (1 - stopPct) → после TP1 = BREAKEVEN stop
        └── TP STAGES: trigger_mult × entry_price_sol
```

### TP Strategy (FEAR режим, T1 $30k-$80k liq)

```
Stage 1: 1.22x → sell 60%  (lock majority at +22%)
Stage 2: 1.48x → sell 50% остатка (=20% original)
Stage 3: 2.00x → sell всё (moon bag)
Stop: 8% ниже входа (после TP1 → breakeven stop = entry price)
Early Trail: peak − 3.5% (fires когда trail > entry × 1.02)
Trail: 15% от peak (после TP1)
Hard Cap: 30 min (T1)
```
